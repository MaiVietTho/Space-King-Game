# Getting Started

**English** · [Tiếng Việt](00-huong-dan-bat-dau.md)

How to set up the environment, build and flash Space King onto the AK Embedded Base Kit, and how the source code is organized.

## I. Environment

| Item | Notes |
|---|---|
| OS | Ubuntu / Linux |
| Editor | VSCode (recommended) |
| Toolchain | [Arm GNU Toolchain](https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads) `arm-none-eabi` (tested with **15.3.rel2**) |
| Flashing | `ak-flash` (included in this repo) or ST-Link + STM32CubeProgrammer |
| Console | `minicom` |

### Toolchain configuration

Open [`ak-base-kit-stm32l151/application/Makefile`](../ak-base-kit-stm32l151/application/Makefile) and point `GCC_PATH` to your toolchain folder:

```make
GCC_PATH = $(HOME)/Documents/arm-gnu-toolchain-15.3.rel2-x86_64-arm-none-eabi
```

The `LIBGCC`, `LIBGCOV` and `LIB_PATH` paths contain the **GCC version** (`.../lib/gcc/arm-none-eabi/15.3.1/...`). Update it whenever you switch toolchains, otherwise the link step fails with:

```
make: *** No rule to make target '.../lib/gcc/arm-none-eabi/<version>/thumb/v7-m/nofp/libgcc.a'
```

Find the right version with `ls $GCC_PATH/lib/gcc/arm-none-eabi/`.

## II. Build

```sh
cd ak-base-kit-stm32l151/application
make -j3
```

Output in `build_ak-base-kit-stm32l151-application/`:
- `ak-base-kit-stm32l151-application.axf`: ELF file (for debugging)
- `ak-base-kit-stm32l151-application.bin`: image to flash

`make help` lists the other targets (`flash`, `com`, `debug`, `clean`, `asm`, `sym`).

## III. Flashing

The application lives at **`0x08003000`**, after the bootloader (`0x08000000`) and the BSF shared-data area (`0x08002000`).

### Option 1: over USB with `ak-flash` (recommended)

Requires a board that **already has the AK bootloader** (kits normally ship with it).

```sh
# Install ak-flash once
cd ak-flash
make
sudo make install

# Flash
cd ../ak-base-kit-stm32l151/application
make flash dev=/dev/ttyUSB0
```

If `/dev/ttyUSB0` is not accessible, add your user to the `dialout` group (`sudo usermod -aG dialout $USER`) and log in again.

### Option 2: over ST-Link (SWD)

Use this for a blank chip or to reflash the bootloader. Install STM32CubeProgrammer, set `PROGRAMER_PATH` in the Makefile to its `bin` folder, then:

```sh
make flash
```

## IV. Debug console

```sh
make com dev=/dev/ttyUSB0      # minicom at 115200 baud
```

`APP_DBG(...)` / `APP_DBG_SIG(...)` logs are printed to this console.

## V. Game source layout

```
ak-base-kit-stm32l151/application/sources/app/
├── app.h                       # Signals and timer intervals of every task
├── app.cpp                     # System init, display start-up timer
├── app_bsp.cpp                 # MODE / UP / DOWN button callbacks
├── app_eeprom.h                # EEPROM addresses, setting / save-data structs
├── task_list.cpp               # Task table: ID, priority, handler
├── task_display.cpp            # Display task -> screen manager
├── game/spacecraft_game/       # One task per game object
│   ├── sc_game_spacecraft.*    # Player spacecraft
│   ├── sc_game_arrow.*         # Player arrows
│   ├── sc_game_enemy.*         # Enemies (rounds 1-3)
│   ├── sc_game_arrow_enemy.*   # Enemy shots
│   ├── sc_game_meteoroid.*     # Meteoroids (round 4)
│   ├── sc_game_boss.*          # Boss (round 5)
│   ├── sc_game_boss_skill.*    # Energy ball, laser
│   ├── sc_game_gift.*          # Gifts (heart, arrow power)
│   ├── sc_game_bang.*          # Explosion effect
│   └── sc_game_starfield.*     # Background
└── screens/
    ├── scr_startup / scr_info / scr_idle      # Startup, info, screensaver
    ├── scr_menu_game / scr_game_setting       # Menu, settings
    ├── scr_game_change_round                  # Round transition screen
    ├── scr_spacecraft_game                    # Main game screen + round / tick control
    ├── scr_game_over                          # Game over
    └── screens_bitmap.*                       # All bitmaps
```

### Adding a new object

1. Add a task ID to `task_list.h` and a row to the table in `task_list.cpp` (priority `TASK_PRI_LEVEL_4` like the other objects).
2. Define its signals and intervals in `app.h` (following the `SC_GAME_..._SETUP / _RESET` pattern).
3. Write `sc_game_<object>.cpp/.h` with a `sc_game_<object>_handle(ak_msg_t* msg)` handler.
4. Add the source file to `game/spacecraft_game/Makefile.mk`.
5. Send its SETUP signal in `scGameSpacecraftRoundSetup`, its RESET in `SC_GAME_RESET`, and its update signals in `scGameSpacecraftTimeTick` (`scr_spacecraft_game.cpp`).
6. Draw the object in `view_scr_spacecraft_game()`.

## VI. Regenerating diagrams and images

The sequence diagrams and bitmap images in the docs are generated by scripts (Python 3 + Pillow):

```sh
python3 tools/gen_diagrams.py   # -> resources/diagrams/*.drawio.svg
python3 tools/gen_bitmaps.py    # -> resources/images/bitmap/*.png, *.gif
```

The `.drawio.svg` files open directly in [draw.io / diagrams.net](https://app.diagrams.net/) for manual edits. Note: rerunning `gen_diagrams.py` overwrites manual edits, so once a diagram is edited in draw.io, keep editing it there.

Details (editing diagram content, update workflow, common errors): [tools/README.md](../tools/README.md) (Vietnamese).
